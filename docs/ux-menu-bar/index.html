01 / DIAGNOSIS

문제는 공간보다, 흐름에 있습니다.

현재 기능은 충분합니다. 메뉴 안의 정보 우선순위와 상태 전환을 다듬으면 일상 사용이 짧아집니다.

사용하는 순간현재 코드의 동작바꿀 경험
새 버전 확인맥락 유지확인 중에는 기존 목록 대신 짧은 로딩 메뉴가 나옵니다.읽던 목록을 유지하고 확인 상태만 갱신합니다. 실행 버튼은 잠시 비활성화합니다.
업데이트 선택실행 의도 분리이름과 버전이 적힌 메뉴 항목을 누르면 즉시 업데이트합니다.선택·상세 보기·실행의 역할을 나눕니다. 실행 버튼에서 대상 개수를 확인합니다.
명령 승인앞뒤로 한 단계서비스 → 필드 하위 메뉴 → 확인창을 거쳐 명령을 검토합니다.팝오버 안에서 정확한 명령과 작업 폴더를 읽고, 해당 명령만 승인합니다.
진행 확인같은 자리에서진행 이벤트마다 메뉴 전체를 다시 만들며, 깜빡임을 줄이기 위한 지연 처리가 있습니다.각 행의 대기·실행·완료 상태만 갱신합니다. 닫기는 작업을 중단하지 않습니다.

근거: MenuBarMenuModel.swift · UpdateBarMenuBarApp.swift · ManageItemsPanelController.swift. 코드에 근거한 UX 가설이며 사용 시간은 아직 실측하지 않았습니다.

03 / IMPLEMENTATION PLAN

이미 있는 기능 위에, 순서대로.

기존 서비스·명령 승인·업데이트 조정자를 재사용합니다. 네이티브 적용은 아래 세 단계로 나눕니다.

PHASE 01

일상 흐름

NSStatusItem에 작은 NSPopover를 연결합니다. 고정 헤더·선택 목록·실행 버튼을 구성하고, 확인 중에도 목록을 유지합니다.

완료 조건

0·1·30개 목록, 키보드 선택, 긴 이름, 작은 화면에서도 실행 버튼이 보입니다.

PHASE 02

진행과 복구

항목별 진행·명령 검토·일부 실패 재시도를 연결합니다. 중단 시 실행 중인 항목은 끝내고 대기 작업은 시작하지 않습니다.

완료 조건

닫고 다시 열어도 진행 유지. 미승인 명령 제외. 병렬 실행·중단·재시도 동작 확인.

PHASE 03

관리 연결과 마감

Items·Scan & Add·Logs·Settings로 바로 연결합니다. 파일 상태 감시와 오류 복구 경로를 유지하고 접근성을 다듬습니다.

완료 조건

실제 앱에서 VoiceOver·다크 모드·여러 모니터·Dock 복귀 검증. 관련 테스트와 quality gate 통과.

구현 연결점과 검증 범위

추가할 UI: MenuBarPopoverController, MenuBarPopoverView, MenuBarPopoverModel. 기존 MenuBarActionCoordinator, MenuBarItemProgress, MenuBarServicing을 재사용합니다. 코어의 실행·승인 경계는 유지합니다.

작업 상태: 팝오버 밖에 보관합니다. 열기만으로 새 버전 확인을 시작하지 않습니다. 실행률을 모르는 명령에는 가짜 퍼센트 대신 완료 항목 수를 표시합니다.

이번 HTML: 선택·상세·승인·확인·업데이트·중단·재열기·재시도를 예시 데이터로 시연합니다. Dashboard 연결 버튼은 연결 설계 설명을 엽니다. 실제 명령 실행과 AppKit 접근성은 네이티브 구현 단계에서 검증합니다.

참고: Apple은 데이터가 많은 메뉴바 기능에 MenuBarExtra의 window 스타일을 제시합니다. AppKit 기반의 현재 앱에서는 NSPopover의 transient 동작을 출발점으로 검토합니다.
