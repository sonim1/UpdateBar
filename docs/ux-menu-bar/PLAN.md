# UpdateBar 메뉴바 UX 개선안

2026-09-09 · 검토용 설계 · 네이티브 앱 적용 전

## 목표와 범위

기능의 가치는 유지하면서, 메뉴바를 열고 업데이트를 끝내는 일상 흐름을 짧게 만든다. 이번 산출물은 코드 근거를 포함한 계획과 로컬 HTML 인터랙션 프로토타입이다. 버전·명령·결과는 예시이며 실제 업데이트, 승인, 설정 변경을 실행하지 않는다.

가정: macOS 13 이상, 메뉴바가 기본 진입점, 기존 Dashboard와 CLI/Core를 유지한다. UI 카피는 검토하기 쉽게 한국어로 제안한다. 현재 앱의 라이브 화면은 도구에서 식별되지 않아 진단은 소스와 현재 문서에 근거한다.

성공 기준: 팝오버를 연 뒤 승인된 업데이트는 한 번의 명시적 실행으로 시작한다. 선택 업데이트는 체크박스로 범위를 조절한다. 확인·실행 중 목록이 유지되고 닫았다 열어도 작업 상태가 이어진다. 승인·실패·최신·첫 실행 상태에 다음 행동이 분명하다.

## 대안 비교

| 안 | 장점 | 비용·제약 | 판단 |
| --- | --- | --- | --- |
| A. 현재 NSMenu 정리 | 가장 작은 변경. 기본 메뉴 키보드 동작 재사용. | 다중 선택·상세 검토·지속적인 진행 표시에 한계가 남는다. | 빠른 임시 개선용 |
| B. 작은 팝오버 + 기존 Dashboard | 메뉴바에서 확인·선택·진행·결과가 이어진다. 고급 기능은 기존 창 재사용. | 팝오버 포커스·닫힘·접근성·화면 경계 처리를 구현해야 한다. | **추천** |
| C. Dashboard 중심 앱 | 큰 목록·검색·관리에 공간이 충분하다. | 일상 업데이트에도 작업 전환이 필요하다. 메뉴바의 장점이 줄어든다. | 이번 목표와 맞지 않음 |

Apple의 [MenuBarExtra 문서](https://developer.apple.com/documentation/swiftui/menubarextra)는 복잡하고 데이터가 많은 메뉴바 기능에 window 스타일을 제시한다. 이 프로젝트는 AppKit 기반이므로 기존 NSStatusItem에 NSPopover를 연결하는 경로를 우선 검토한다. [NSPopover transient 동작](https://developer.apple.com/documentation/appkit/nspopover/behavior-swift.enum/transient)은 바깥 상호작용으로 닫힐 수 있으므로 작업 상태는 뷰 밖에 둔다. 정확한 닫힘 제스처는 네이티브 QA에서 확인한다.

## 추천 구조

1. 메뉴바: 단색 아이콘 + 실행 가능한 업데이트 개수. 확인·실행 중에는 진행 기호. 실패는 `!`, 승인 대기는 별도 상태 설명. 색만으로 구분하지 않는다.
2. 헤더: UpdateBar / 마지막 확인 시점 / ‘지금 확인’. 새로 확인할 때 기존 목록 유지.
3. 본문: 업데이트 목록. 기본적으로 승인되고 업데이트 가능한 항목만 선택. 체크박스는 실행 범위, 제목 버튼은 상세 보기.
4. 주의 영역: 승인 필요·실패는 별도 한 줄 요약. 전체 업데이트에 미승인 명령을 섞지 않는다.
5. 고정 실행 영역: ‘선택한 3개 업데이트’. 대상 0개이면 이유를 보여주며 비활성화. 승인된 항목은 추가 확인 모달 없이 실행한다.
6. 보조 영역: ‘전체 관리 열기’와 최근 결과. 통계 차트·Templates·설정·앱 자체 업데이트·Quit는 Dashboard 또는 작은 보조 메뉴로 연결한다. 도구 버전 확인과 UpdateBar 앱 자체 업데이트를 같은 표현으로 부르지 않는다.

제안 크기: 폭 392pt, 최대 높이 560pt. 본문만 스크롤하고 헤더·실행 영역은 고정한다. 짧은 화면에서는 available visibleFrame에 맞춰 높이를 줄인다. 팝오버를 끌어내 별도 창으로 만드는 기능은 이번 범위에서 제외한다.

## 상태와 상호작용

| 상태 | 보여줄 내용 | 다음 행동 |
| --- | --- | --- |
| 업데이트 있음 | 개수, 선택된 항목, 현재 → 대상 버전, 승인 필요 요약 | 선택 업데이트 / 항목 상세 |
| 확인 중 | 이전 목록, 마지막 성공 확인 시간, 확인 표시 | 기다리기 / 전체 관리. 중복 확인·변경은 비활성화 |
| 실행 중 | 완료 개수/실행 대상 전체, 항목별 실행·대기·완료, 최근 작업 | 실행 중인 항목 완료 후 중단 / 닫기 |
| 중단 요청 | 현재 실행 중인 항목이 끝나면 새 작업을 시작하지 않는다는 설명 | 완료까지 기다리기. 중복 중단 비활성화 |
| 성공 | 성공 개수와 결과, 남은 업데이트·승인 필요가 있으면 그대로 유지 | 결과 보기 / 업무로 돌아가기 |
| 일부 실패 | 성공한 항목 유지, 실패 이유 한 줄, 실패한 항목 식별 | 실패 항목만 재시도 / 상세 로그 |
| 승인 필요 | 명령 필드, 정확한 command·cwd·승인 여부 | 해당 명령만 명시적으로 승인. 승인이 업데이트를 실행하지 않음 |
| 모두 최신 | 마지막 확인 시점과 조용한 완료 상태 | 지금 확인 / 전체 관리 |
| 첫 실행 | 추적 중인 도구 없음, ‘설치된 도구 찾기’ | 기존 Scan & Add로 이동. 검색·등록·명령 승인을 별도 단계로 유지 |

닫기/Escape는 실행 취소가 아니다. 다시 열면 동일한 상태·선택·스크롤 위치로 돌아온다. 열린 상태의 선택·스크롤 보존과 화면 리더 알림은 네이티브 적용 시 완료 조건이다. HTML은 닫기·재열기·선택·실행·중단·결과 흐름을 데모 상태로 시연한다.

명령 변경으로 fingerprint가 달라지면 기존 승인은 무효가 된다. 승인·취소·오류 정보는 기존 redaction 규칙을 유지한다. 실제 실행률이나 다운로드 바이트를 알 수 없는 작업에는 가짜 퍼센트/남은 시간을 표시하지 않는다. 진행 막대는 완료 항목 수만 표현한다. 병렬 실행 중 중단은 실행 중인 모든 항목을 기다리고, 대기 항목을 시작하지 않는다.

## 네이티브 구현 순서

### 1. 팝오버와 일상 목록

- 새 `Sources/UpdateBarMenuBarApp/MenuBarPopoverController.swift`: status item anchor, transient 동작, 화면 경계·포커스·Escape 처리.
- 새 `Sources/UpdateBarMenuBarApp/MenuBarPopoverView.swift`: 기존 SwiftUI hosting 패턴을 따라 안정적인 헤더/행/본문/실행 영역.
- 새 `Sources/UpdateBarMenuBar/MenuBarPopoverModel.swift`: 선택된 ID, 탐색 화면, UI 표시 상태. 업데이트 가능 여부는 기존 모델에서 가져온다.
- `UpdateBarMenuBarApp.swift`의 status button 진입과 `rebuildMenu()` 연결을 바꾼다. 기존 NSMenu는 우클릭 보조 명령 또는 오류 복구 경로로 재사용한다.
- 검증: 여러 화면·메뉴바 위치·외부 클릭·Escape·키보드 순서·VoiceOver, 0/1/6/30개 목록, 긴 이름, 고정 footer, 기존 접근성 상태 라벨.

### 2. 진행·실패·명령 검토

- `MenuBarActionCoordinator`, `MenuBarItemProgress`, 서비스의 업데이트·승인 API를 재사용한다. 코어 실행·신뢰 모델은 그대로 둔다.
- `progressHandler`의 이벤트를 팝오버 모델에 반영한다. 전체 뷰를 교체하지 않는다.
- 기존 확인의 exact command·cwd 정보를 팝오버 검토 화면에 연결한다. 변경된 명령은 재승인한다.
- 검증: 다중 선택, 동시 실행 제한·동일 도구 직렬 실행, 실행 중 닫기/재열기, 중단 후 대기 항목 미실행, 일부 실패 재시도, CLI adapter의 coarse progress 표기, 미승인 명령 일괄 실행 제외.

### 3. 기존 Dashboard 연결과 마감

- `showWindowAndReload(selecting:)`로 Items / Scan & Add / Logs / Settings에 직접 연결한다.
- 파일 감시·generation gate·scan mutation gate·error recovery를 보존한다. 팝오버 열기 자체는 새 네트워크 check를 시작하지 않는다.
- 검증: Dashboard와 팝오버의 동시 상태 일치, scan 결과 만료 처리, Sparkle 앱 업데이트·Quit 접근성, 밝게/어둡게·Reduce Motion·Increase Contrast, 앱 활성화 정책·Dock/Cmd-Tab 복귀.
- 완료 게이트: 관련 Swift 테스트와 quality gate 통과 후 패키징한 앱의 실제 메뉴바에서 전 흐름을 수행한다.

## 검증할 사용자 경험 가설

5분 확인: 업데이트 가능한 항목 수를 말하기 → 한 항목 제외하고 실행 → 팝오버 닫았다 진행 확인 → 실행 중인 항목 완료 후 중단 → 미승인 명령 확인 → 실패 항목만 재시도. 실행 전 대상을 잘못 예상하거나 진행 상태를 찾지 못하는 순간을 기록한다. HTML 평가는 흐름 검토이며 NSMenu 대비 체감 개선과 시스템 접근성은 실제 앱에서 다시 검증한다.
