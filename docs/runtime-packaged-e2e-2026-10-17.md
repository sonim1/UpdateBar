# Node 런타임과 패키징 앱 E2E 개선

사용자가 승인한 후속 작업 1번(Node 지원·CI)과 2번(패키징된 macOS 앱의
전체 사용 흐름 E2E)을 구현했다. VoiceOver와 별도 최소 창 크기 개선은
이번 범위에서 제외했다.

## 런타임 지원 기준

기존 Node 20 안내와 CI는 잠긴 Ink·ESLint 의존성의 실행 조건과 맞지 않았다.
패키지와 lockfile의 루트 `engines`를 `^22.13.0 || >=24.0.0`으로 맞추고,
macOS 품질 검사에는 Node 24를 사용한다. 의존성 버전은 변경하지 않았다.

별도 Linux 행렬은 Node 22.13.0, 최신 22·24·26에서 같은 TUI smoke를 실행한다.
각 행은 `npm ci --engine-strict`, 타입 검사, 152개 테스트, lint, build,
npm 배포 파일 검사를 수행한다. 최저 지원 버전에서 설치가 깨지는 변화도
CI가 발견할 수 있다.

로컬 실제 PTY에서는 Node 22.22.2·24.19.0·26.5.1의 메뉴 렌더링, 아래 방향키
이동, `q` 종료 코드 0과 대체 화면 복원을 확인했다. 디스크 부족 때문에
기존 컴파일 산출물을 사용했으며, TUI 소스가 기준 커밋 `2be17a8`과 동일함을
확인했다. 이 PTY의 CLI는 0.6.33이며, 변경된 Core의 새 빌드는 원격 CI가
별도로 검증한다.

## 실제 앱 경계를 통과하는 검사

XCUITest가 `dist/UpdateBar.app`을 직접 실행한다. 앱의 컨트롤러를 시험용
호스트에 넣거나 서비스를 대체하지 않는다. 각 시나리오는 새 임시 HOME,
CFFIXED_USER_HOME, UPDATEBAR_HOME을 사용하고, 외부 도구 실행은 시험용
실행 파일로 한정한다. 저장 상태는 앱에 포함된 CLI의 읽기 명령으로 확인한다.

| 시나리오 | UI 동작과 검사 조건 |
| --- | --- |
| 최초 등록부터 재실행까지 | 메뉴바 → Dashboard → Items → Scan → 등록 → 정확한 check/update 명령 확인·승인 → Check → Update → Logs. 1.0.0에서 2.0.0으로 바뀌고 재실행 뒤 항목·승인·상태·이력이 유지되어야 한다. |
| 종료 코드 0인 무효 업데이트 | 명령은 성공 종료하지만 버전 파일은 1.0.0으로 유지한다. 결과는 failed, 관찰 버전은 1.0.0, 목표는 2.0.0, 종료 코드는 0이어야 하며 Logs 상세에도 표시되어야 한다. |
| 등록 없는 반복 스캔 | 발견 결과를 두 번 조회하되 항목·승인·업데이트 이력을 만들지 않는다. 두 번째 외부 도구 호출과 UI의 스캔 완료까지 기다린다. |

등록 직후에는 승인 상태가 모두 미승인이어야 하고 업데이트 버튼도 비활성이다.
각 승인 버튼은 해당 명령의 확인 체크 전까지 비활성이어야 한다. 승인이나
검사만으로 실제 업데이트 명령이 실행되지 않았는지도 함께 확인한다.

GUI 앱은 표준 도구 경로를 PATH에 추가한다. 따라서 시험 PATH만 짧게 지정하는
것으로는 격리가 충분하지 않다. Brew·npm뿐 아니라 알려진 버전 조회 도구를
모두 임시 실행 파일로 가린다. 생산 코드에 PATH 발견을 우회하는 시험 분기는
추가하지 않았다. 완전히 빈 발견 결과는 기존 컨트롤러·모델 검사로 보호한다.

E2E는 앱 패키징 이후 필수 `macos` CI 작업에서 실행된다. 일반 로컬 품질 검사는
GUI 없이 실행할 수 있도록 runner·workflow 계약만 검사한다. CI의 실제 GUI
검사 실패는 필수 검사 실패로 이어지고, macOS 작업은 최대 30분으로 제한한다.
성공·실패 모두 화면, 접근성 트리, manifest/state/history와 외부 명령 기록을
`.xcresult` 아티팩트에 7일간 보관한다. 이미 실행 중이던 사용자 앱은 시험이
종료하지 않는다.

## E2E에서 발견한 Homebrew 버전 오류

스캔으로 생성하는 Brew 레시피는 출력에서 처음 나오는 숫자를 버전으로 읽었다.
이 때문에 도구 이름의 숫자가 실제 설치 버전보다 먼저 매칭됐다.

| 출력 | 기존 추출값 | 수정 후 추출값 |
| --- | --- | --- |
| `node@22 22.22.0` | `22` | `22.22.0` |
| `python@3.13 3.13.7` | `3.13` | `3.13.7` |
| `e2e-fixture 1.0.0` | `2e-fixture` | `1.0.0` |
| `jq 1.7.1_2` | `1.7.1_2` | `1.7.1_2` |

새 회귀 테스트가 수정 전 세 오류를 재현했다. 생성되는 정규식 한 줄을
`^\S+\s+([0-9][0-9A-Za-z._+-]*)`로 바꿔 전체 formula 이름 다음의 버전을
읽도록 했다. revision 접미사를 유지하는 인접 회귀 검사도 포함했다.
이 변경은 새로 생성하는 스캔 레시피에 적용된다. 기존 사용자 레시피와 승인
기록을 자동으로 다시 쓰는 마이그레이션은 포함하지 않는다.

## 검증 기록과 제한

구현 커밋 `8a759a0`의 원격 전체 품질 검사에서 macOS Swift 986개가 통과했고,
Linux는 907개 중 플랫폼별 2개를 건너뛰고 실패 없이 통과했다. 네 Node 행도
모두 통과했다. 실제 앱의 정상 업데이트·재실행과 반복 스캔도 이 빌드에서
통과했다. 무효 업데이트의 상태 검증 후 실패한 상세 화면 조회는 ScrollView의
식별자를 TextView 식별자로 사용한 테스트 오류였다. 실제 접근성 트리를 보고
기존 ScrollView 안의 TextView를 찾도록 바로잡았다.

최종 커밋의 전체 검증 결과와 GUI 증거는 [PR #95](https://github.com/sonim1/UpdateBar/pull/95)의
정확한 head SHA에 연결된 CI 실행에서 확인할 수 있다. 로컬 원본 기록은
`.omo/evidence/runtime-packaged-e2e-20261017/`에 보존하며 공개 배포에 넣지 않는다.
실행 명령과 결과 경로는 [개발 안내](development.md#packaged-app-e2e)에 있다.

로컬 전체 품질 검사는 `ENOSPC`로 컴파일을 마치지 못했다. 재생성 가능한
이번 작업의 임시 산출물을 정리하고 원격의 새 빌드로 검증했다. 기존 사용자
앱이 실행 중이어서 로컬 GUI 인스턴스를 종료하거나 바꾸지 않았다. GUI 동작은
격리된 GitHub macOS 데스크톱의 실제 OS 자동화와 그 화면·상태 증거로 확인한다.
VoiceOver 음성 출력 시험은 요청에 따라 수행하지 않는다.
